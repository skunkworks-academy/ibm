# Part 3: Security and Concurrency

**Self-paced allocation:** 6 hours · **Official unit structure:** 3 units

Concurrency protects correctness while simultaneous transactions share data; security constrains which identities may perform those actions. Both require precise evidence about identity, scope, state and transaction context.

## Unit 1 · Locking and Concurrency Control

Db2 serialization mechanisms include locking, versioning and latching. Isolation levels UR, CS, RS and RR change which anomalies are permitted and how long protection is retained.

A lock wait, timeout, deadlock and escalation are different conditions:

- **wait:** incompatible access is temporarily blocked;
- **timeout:** the configured wait boundary is exceeded;
- **deadlock:** a dependency cycle requires a victim;
- **escalation:** many fine-grained locks are replaced by a broader lock to protect lock-list resources.

Investigate holder, waiter, object, modes, unit-of-work age, SQL and isolation before considering termination.

## Unit 2 · Security and Access Control Fundamentals

Authentication establishes identity. Authorization determines what the authenticated identity may do. Investigate these as separate failure domains.

Understand the hierarchy of instance-, database-, schema-, tenant- and object-level controls, and map duties to the minimum sufficient privilege or role. Broad authorities are not convenience permissions.

Task authorities called out in this unit include **SECADM, DBADM, ACCESSCTRL and DATAACCESS**. Their separation supports least privilege and separation of duties.

```sql
CREATE ROLE REPORT_READER;
GRANT SELECT ON TABLE APP.SALES_SUMMARY TO ROLE REPORT_READER;
GRANT ROLE REPORT_READER TO USER ANALYST1;
```

## Unit 3 · More about Db2 Security and Access Control

This unit covers secure database connections, RCAC, trusted contexts, LBAC and auditing.

### Encryption in transit

Use supported TLS configuration and govern certificate validity, trust stores, hostname verification, protocol selection, key ownership and renewal. “Encryption enabled” is not a complete control description.

### RCAC and LBAC

RCAC row permissions and column masks enforce fine-grained business policy close to the data. LBAC uses security labels and authorizations for classification-style policy. Choose the model that matches the policy rather than stacking controls by default.

### Trusted contexts

A trusted context supports controlled identity switching/delegation in tiered applications under defined trust conditions. It should improve attribution and control, not hide user identity.

### Auditing

Define which privileged or sensitive events must be attributable, where audit data is protected, who reviews it, and how long it is retained.
